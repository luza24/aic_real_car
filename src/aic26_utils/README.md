# aic26_utils

Shared utility nodes and launch files for the AIC26 stack.

| Node | Purpose |
| --- | --- |
| `camera_view.py` | OpenCV window for a camera topic |
| `speech_broadcaster.py` | `/speech` text -> Kokoro TTS -> Bluetooth speaker |
| `kokoro_worker.py` | TTS worker, runs in a separate Python 3.10+ venv |

## Speech output (Kokoro + Bluetooth speaker)

```
mission_controller --/speech--> speech_broadcaster --stdin/stdout-->
    kokoro_worker (venv, py3.10+) --paplay--> Bluetooth speaker
```

The mission side only publishes `std_msgs/String` on `/speech`; nothing else
depends on the speech node. Announcements are generated by
`aic26_decision/scripts/mission_common.py` (`format_result_message`): Chinese
people/car results, and no message at all when the checkpoint has no fresh
result. An `inspect` task can set `announce: false` to inspect silently.

Kokoro needs **Python 3.10-3.12**, while ROS Noetic runs Python 3.8. The ROS
node therefore never imports Kokoro: it keeps `kokoro_worker.py` alive in a
separate virtual environment.

### One-time setup (on the car)

```bash
sudo apt install espeak-ng pulseaudio-utils
bash ~/aic26_ws/src/aic26_utils/scripts/setup_kokoro.sh
```

The script creates `~/aic26_kokoro_venv` (override with
`AIC26_KOKORO_VENV=/path`), installs `kokoro`, `soundfile` and `misaki[zh]`,
and downloads the 82M model + voice. The first install needs network access
and about 2 GB of disk (mostly the CPU build of torch). It also writes
`/tmp/aic26_kokoro_check.wav` with the sentence "语音播报测试".

### Find the Bluetooth sink

Pair and trust the speaker first (`bluetoothctl`), then:

```bash
pactl list short sinks | grep bluez
# bluez_output.AC_12_2F_XX_XX_XX.1   ...
```

The sink name is based on the speaker's MAC and normally survives
reconnects. Use the full name after `bluez_output.`.

### Run

Start it next to the running robot stack (it is intentionally not part of
`aic26_bringup`):

```bash
roslaunch aic26_utils speech.launch \
    sink:=bluez_output.AC_12_2F_XX_XX_XX.1
```

Check it without the robot:

```bash
rostopic pub -1 /speech std_msgs/String \
    "data: '本区域共检测到 12 人，其中 2 人为非社区人员。'"
```

A newer message interrupts the one being spoken. The mission never waits for
playback.

### Test the worker directly (no ROS)

```bash
# synthesize and save
~/aic26_kokoro_venv/bin/python \
    aic26_utils/scripts/kokoro_worker.py \
    --check --out /tmp/test.wav

# synthesize and play through the speaker
paplay --device=<sink> /tmp/test.wav
```

`kokoro_worker.py --check` is also what the setup script runs.

### Useful launch arguments

| Argument | Default | Notes |
| --- | --- | --- |
| `sink` | empty | PulseAudio sink; empty uses the default output |
| `voice` | `zf_xiaoxiao` | also `zf_xiaobei`, `zf_xiaoni`, `zf_xiaoyi`, `zm_yunjian`, `zm_yunxi`, `zm_yunxia`, `zm_yunyang` |
| `lang` | `z` | `z` = Mandarin, `a` = American English |
| `speed` | `1.0` | speech rate |
| `threads` | `2` | torch threads; lower to `1` if perception slows down |
| `volume` | `100` | percent |
| `tts_python` | `~/aic26_kokoro_venv/bin/python` | venv created by the setup script |
| `enabled` | `true` | disables the node without stopping the mission |

### Offline contests

The model and voices are cached in `~/.cache/huggingface`. After one online
warm-up, copy that directory to the car (or set `HF_HOME` to it) and export

```bash
export HF_HUB_OFFLINE=1
```

before starting `speech.launch`. The worker starts from the cache without
network access.

### Troubleshooting

- **No sound**: check `pactl info` works in this shell (PulseAudio belongs to
  the logged-in user session; over SSH use the same user), verify the sink
  name, and test `paplay --device=<sink> /tmp/test.wav`.
- **`speech worker ready` never appears**: run the venv python directly; a
  missing package prints the import error. Chinese needs `misaki[zh]` and the
  system `espeak-ng`.
- **Announcements are stale**: the mission still waits `detect_wait` (1 s)
  after triggering a detector. Car plate OCR can take longer, in which case
  the announcement says the plate was not recognised.
- **Perception slows down**: start the launch with `threads:=1`; the worker
  also runs at a lower `nice` level.
